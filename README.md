# pdf-video-examples

Small PDF files with video and sound in annotations, for testing PDF viewers
and PDF writers: how they play media, start it on page open and find embedded
files. The media are synthetic and generated by a script, so the files can be
copied freely, e.g. into a project's test suite (see [License](#license)).

01 to 07 are uncompressed PDF 2.0 files written with pdfLaTeX, so they can be
read in a text editor (except the media data). 08 is written by LibreOffice:
PDF 1.7, compressed and tagged, as LibreOffice exports by default. The media
are embedded as embedded file streams, so each PDF is self-contained, except
`04-linked.pdf`.

| File | Content |
|---|---|
| `01-embedded-click.pdf` | Screen annotation, embedded video, played on click |
| `02-embedded-autostart.pdf` | Screen annotations, embedded video, also played on page open (`/AA /PO`); on page 1 (opened with the document) and page 2 (opened by navigating; with the second clip) |
| `03-embedded-two-pages.pdf` | Screen annotations, the same video on two pages: one embedded file, two annotations |
| `04-linked.pdf` | Screen annotation, linked video (`clip.mp4` must be next to the PDF) |
| `05-embedded-audio.pdf` | Screen annotation, embedded sound (WAV), played on click |
| `06-richmedia-click.pdf` | RichMedia annotation (video instance), embedded video, activated on click (`/XA`) |
| `07-richmedia-autostart.pdf` | RichMedia annotations (video instance), embedded video, activated on page open (`/PO`); on page 1 and page 2 (with the second clip), as in 02 |
| `08-libreoffice-click.pdf` | Converted by LibreOffice Impress 26.2 from `08-libreoffice-click.pptx` (PDF 1.7): Screen annotations, embedded video, played on click; two slides, with the two clips |

## Why this is worth supporting now

Playing video from PDF has been notoriously unreliable: viewers either didn't
support it, or handed it to platform-specific media players.

Browsers, on the other hand, play video very well on all operating systems,
since video is everywhere on the web. A PDF viewer that runs in the browser can
use that: pdf.js, Firefox's PDF viewer, plays embedded media in screen and
RichMedia annotations through an HTML5 `<video>`/`<audio>` element since June
2026 ([mozilla/pdf.js#21474](https://github.com/mozilla/pdf.js/pull/21474),
[mozilla/pdf.js#21490](https://github.com/mozilla/pdf.js/pull/21490)). This
avoids most of the old problems, and it is a viewer that almost everyone
already has.

What remains is the choice of format. PDF allows any media type, but a browser
only plays the formats it supports:

- MP4 (H.264 video, AAC audio), WebM (VP9, AV1, Opus), MP3 and WAV are safe
  choices.
- Others, e.g. QuickTime/ProRes, AVI, MPEG-2 or HEVC, don't play, or only on
  some platforms.

A PDF writer usually can't check the codecs inside a file. It could, however,
warn when the media type (e.g. from the file extension) isn't one of the widely
supported web formats.

## Screen and RichMedia annotations

Both annotation types can play embedded media:

- **Screen annotations with media renditions** (ISO 32000-2, 12.5.6.18,
  12.6.4.14 and 13.2) have been part of the standard since PDF 1.5. They are
  widely supported, and the natural first target for a PDF writer.
- **RichMedia annotations** (13.7) were an Adobe extension based on Flash, and
  are part of the standard without Flash since PDF 2.0. Acrobat itself creates
  RichMedia annotations when adding video.

Viewers implement one or the other, or treat them differently: for example,
released versions of Okular start media on page open for RichMedia, but not
for screen annotations (see [Viewers](#viewers)). A PDF writer supporting both,
as an option, covers the most viewers.

## Structure: screen annotations (01 to 05)

Each `\media` call (see [Rebuilding](#rebuilding)) writes:

- a `/Screen` annotation with
  - the poster as its appearance (`/AP /N`, a form XObject),
  - `/P` (the page; required for screen annotations with rendition actions,
    Table 166),
  - `/Contents` (alternative text),
  - `/A` → rendition action `/OP 0` (play; restarts if already playing) on
    click,
  - `/AA /PC` → rendition action `/OP 1` (stop) on page close,
  - with autostart, `/AA /PO` → rendition action `/OP 4` (play, or resume if
    paused) on page open;
- one media rendition (`/S /MR`) shared by these actions, with a media clip
  (`/S /MCD`) giving
  - the file specification `/D` (a file specification dictionary, as Table 285
    requires),
  - the MIME type `/CT` (which, per Table 285, takes precedence over the
    embedded file's `/Subtype`),
  - the alternative text `/Alt` (multi-language text array, 14.9.2.4; the
    empty language identifier marks default text),
  - `/P /TF (TEMPACCESS)`,

  and play parameters requesting controls (`/BE << /C true >>`);
- for embedded media, an embedded file stream (`/Type /EmbeddedFile`, `/Subtype`
  with the MIME type, `/Params /Size`) and a file specification (`/F`, `/UF`,
  `/EF`).

  The file is written once per document and referenced only from the media
  clip, not from the `/EmbeddedFiles` name tree, so viewers don't list it as an
  attachment.

Object 1 (`/R 22050`, empty stream) in these files is not part of the media
support: `multimedia.sty`, which generates them, writes it when loaded, for
beamer's `\sound` command.

## Structure: RichMedia annotations (06, 07)

Written by `richmedia.tex` with pdfTeX primitives:

- an embedded file stream and file specification as above;
- a RichMedia instance (`/Subtype /Video`) in one configuration;
- `/RichMediaContent` with the configuration and the `/Assets` name tree;
- `/RichMediaSettings` with activation (`/XA` or `/PO`) and deactivation
  (`/PC`), presentation style `/Embedded`;
- a `/RichMedia` annotation with appearance, `/P` and `/Contents`.

As required by PDF 2.0 (Table 343), the instance's `/Asset` refers to a file
specification that is also listed in the `/Assets` name tree. pdf.js, and
Okular with poppler 26.10.90 or newer, find the file this way.

In addition, the instance has `/Params << /FlashVars (source=clip.mp4) >>`.
This is not part of PDF 2.0 (a remnant of the Flash-based extension), and
readers that don't need it ignore it. Older poppler versions, and so Okular
with them, only find the file through it.

## Structure: LibreOffice (08)

`make-pptx.py` writes a PowerPoint file with python-pptx, and LibreOffice Impress
converts it to PDF: PDF 1.7, compressed and tagged, LibreOffice's default
(it can also write PDF 2.0, export option `SelectPdfVersion` 20, but that's
not what users get). LibreOffice writes for each
video a `/Screen` annotation with only the click action `/A` (rendition action
`/OP 0`), an embedded file and a media clip with `/CT`, `/Alt` and
`/P /TF (TEMPACCESS)`; no appearance stream, no `/AA`. The poster is part of
the page content, drawn over a dark grey fill of the video area.

There is no LibreOffice example for page open: its PDF export
(`PDFWriterImpl::emitScreenAnnotations()` in `vcl/source/pdf/pdfwriter_impl.cxx`)
writes no `/AA`, so a video that starts automatically in the presentation only
plays on click in the PDF.

The poster is an image of an empty frame, as in the LaTeX examples (without a
poster, python-pptx adds a loudspeaker icon).

## Tagging

01 to 07 are not tagged: no structure tree, no `/StructParent`. They carry
alternative text in the annotation's `/Contents` and, for screen annotations,
also in the media clip's `/Alt`. 08 is tagged by LibreOffice: the annotations
have a `/StructParent`, and the media clip an (empty) `/Alt`.

## Viewers

Tested in Firefox (pdf.js) and Okular (poppler; Fedora's Okular 26.08 and a
build with a fix for
[KDE bug 491780](https://bugs.kde.org/show_bug.cgi?id=491780)):

- **Firefox** plays all embedded media (01 to 08) on click, in screen and
  RichMedia annotations alike. It doesn't start media on page open (02, 07)
  and doesn't play linked files (04).
- **Okular** plays all embedded media (01 to 08) on click; in the page view
  only with the mouse mode "Browse", not "Text Selection".
  - Page open, RichMedia (07): media starts when its page is opened, already in
    Okular 26.08.
  - Page open, screen annotations (02): media starts only with the fix for KDE
    bug 491780
    ([okular!1558](https://invent.kde.org/graphics/okular/-/merge_requests/1558)),
    which isn't merged yet; then it behaves as for RichMedia.
  - In presentation mode, media starts every time its page is shown. In the
    page view of Okular 26.08, it doesn't start again when scrolling back to
    a page; the same fix covers this, for both annotation types.

## Rebuilding

- `make-media.py` generates the synthetic media:
  - `clip.mp4`: a coloured bar moving from left to right on grey, H.264,
    160×90 pixels, 2 s;
  - `clip2.mp4`: a black dot moving from top to bottom on yellow, otherwise
    the same; used on page 2 of 02 and 07, so it's easy to see which page's
    video plays (e.g. in presentation mode);
  - `tone.wav`: 440 Hz, 1 s.

  It needs PyAV and NumPy, e.g. with
  `uv run --no-project --with av --with numpy python make-media.py`.
- `make-pptx.py` writes the PowerPoint file for 08; it needs python-pptx and
  Pillow, e.g. with
  `uv run --no-project --with python-pptx --with pillow python make-pptx.py`.
  `make 08-libreoffice-click.pdf` writes it and converts it with LibreOffice.
  Unlike 01 to 07, these two files differ on every rebuild, but only in
  timestamps: python-pptx stores the current time in the zip entries, and
  LibreOffice writes the creation date and a random file identifier (`/ID`).
- `make` builds the PDFs with pdfLaTeX (or run `pdflatex` on each `0*.tex`):
  - 01 to 05 use `\media` from the `multimedia.sty` in this directory: beamer's
    `multimedia` package with `\media` added, as on the branch
    [`screen-annotations`](https://github.com/awehrfritz/beamer/tree/screen-annotations)
    of https://github.com/awehrfritz/beamer (commit
    [8923423](https://github.com/awehrfritz/beamer/commit/8923423856b2aec06cf18d7a0980f8763f7e53b2)).
    Being in the current directory, it takes precedence over the installed
    beamer version. Use it for these examples only; it is not the
    `multimedia.sty` distributed with beamer.
  - 06 and 07 use only `richmedia.tex`.

`example-setup.tex` sets PDF 2.0, no compression and reproducible output (no
dates, no trailer ID).
